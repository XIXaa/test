# 功能实现和证据矩阵

重要说明：**原 APK 未被当前执行环境访问**，所以没有任何功能可以标注为“与 APK 相同”。以下只是当前 Python 桌面端实现状态。

| 桌面端功能 | 实现状态 | 验证方式 / 限制 |
|---|---|---|
| FFmpeg 后台解码并返回 RGB 帧 | 已实现 | 实际 FFmpeg testsrc 测试通过 |
| 始终只保留最新帧，旧帧不排队 | 已实现 | 单帧槽 + 帧序列号，单元测试通过 |
| 9 路独立运行 | 已实现 | 9 路同时解码压力测试均收到帧 |
| 1/2/4/9 分屏布局 | 代码已实现 | CustomTkinter GUI 尚未启动验证 |
| 极限/均衡/稳定的低延迟解码参数 | 已实现 | FFmpeg 参数检查通过；真实网络效果待测 |
| 手动追直播与自动重连 | 已实现 | 断开重接/无帧看门狗；需真实弱网测试 |
| RTSP/RTMP/HTTP-FLV/HLS/SRT 等 URL 输入 | 已实现通用 FFmpeg 接口 | 具体协议能否播放取决于 FFmpeg 构建与授权 |
| PNG 截图 | 代码已实现 | Pillow API；未完成 GUI 端到端测试 |
| MKV 原码流封装录制 | 代码已实现 | 需真实音视频源端到端测试 |
| FFplay 音频监听 | 代码已实现 | 是独立拉流，音画同步精度未保证 |
| JSON 播放列表/配置/原子保存 | 已实现 | 单元测试通过 |
| Windows 一键启动脚本 | 已提供 | 需要用户 Windows 环境和 Python/FFmpeg |
| APK 包名、权限、组件、DEX 线索审计 | 已提供只读审计脚本 | 需要原始 APK 文件实际可访问 |
| 原 APK 的所有业务逻辑和页面逐项复刻 | 尚未验证/不宣称实现 | 需要读取真实 APK 并逐项核对 |

## 下一轮重点

1. 在可读取 `MultiLive-android-v10.5.4.apk` 的执行环境运行 `analyze_apk.py`，核查 sha256 与代码/资源结构。
2. 用 jadx/apktool 或 Android 运行时抓取页面、交互和协议（不获取未授权的秘密），建立 APK 功能清单。
3. 逐项替换桌面端通用模块，尤其是 APK 可能特有的平台账号、直播间查询、播放线路、弹幕、录像等功能（这些功能目前并未确认原 APK 是否具有）。
4. 在 Windows 端使用真实流检验低延迟、断网恢复、长时间运行以及 CustomTkinter 界面。
